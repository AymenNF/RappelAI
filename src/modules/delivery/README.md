# Delivery boundary

M2-01 creates one durable `outbound_messages` intent per occurrence. M2-02's injectable `ReminderSender` consumes that queue with send-time eligibility checks, versioned template selection and durable attempts. It shares the WhatsApp module's transport, acceptance persistence and receipt reducer. `sendPending` provides a bounded test-service pass. The regular worker does not construct the sender; live sending and WhatsApp budget qualification remain pending. M2-03 implements audited unknown-outcome recovery and bounded retries for reminder and reply attempts; see [recovery](../../../docs/delivery-recovery.md). SQL uniqueness prevents duplicate internal attempts, not exactly-once network delivery. See [delivery](../../../docs/reminder-delivery.md) and [scheduling](../../../docs/reminder-scheduling.md).
